# Agent instructions

This repository uses a portable multi-agent development system. Every agent reads this file first.

## Read order

1. This file.
2. `AGENT_CONFIG.md` — repo-specific rules (environment, tests, commit policy, enabled agents, repo overview document). **Authoritative for anything repo-specific.**
3. `WORKFLOW.md` — the workflow registry and shared rules.
4. The workflow you are running: `.agents/workflows/<name>.md`.
5. Your role file: `.agents/roles/<agent>.md`.
6. The skill you are about to run: `.agents/skills/<skill>/SKILL.md`.
7. The repo overview document, if `AGENT_CONFIG.md` names one. Do not assume it is called `ARCHITECTURE.md`, and do not assume it exists.

If `AGENT_CONFIG.md` is missing, or still contains `<PLACEHOLDER>` markers, run the `bootstrap` skill before doing anything else.

## Workflows and skills

A **skill** is one unit of work; a **workflow** composes skills into a sequence with its own rules. Both are discovered by listing a directory — no file hard-codes either list.

- Skills: subdirectories of `.agents/skills/`.
- Workflows: files in `.agents/workflows/`.

**Idea to code** is the default workflow. Any other workflow is opt-in and must be explicitly requested; if the user's intent is unclear, ask before starting one — never enter an autonomous workflow by inference.

Agent-specific directories (`.claude/skills/`, `.codex/skills/`, `.grok/skills/`) contain per-skill symlinks back to `.agents/skills/`. If a skill is not visible in your skill registry, read `.agents/skills/<skill>/SKILL.md` directly.

A skill's `Output format` section is the return contract. Role files describe judgment and emphasis; they never define a competing output format.

## Universal safety rules

These hold in every repo, regardless of skill:

- Do not stage, commit, or push unless `AGENT_CONFIG.md` permits it or the user explicitly asks.
- Do not edit files outside this repository.
- Do not modify generated-output directories (see `AGENT_CONFIG.md`) unless explicitly asked.
- Do not run expensive or long-running jobs unless explicitly asked.
- Stay inside the requested scope; if the scope needs to grow, say so first.
- Do not hide failures, and do not claim success that validation does not support.
- Distinguish confirmed facts from inference.

## Document map

```text
AGENTS.md            entry point and universal rules (portable)
WORKFLOW.md          workflow registry, agents, delegation (portable)
CLAUDE.md            thin loaders; each points to .agents/roles/<agent>.md
CODEX.md
GROK.md
AGENT_CONFIG.md      ALL repo-specific agent rules (generated by `bootstrap`)
README.md            how humans run this repo — not duplicated into agent docs
.agents/skills/      canonical skill definitions
.agents/workflows/   workflow definitions
.agents/roles/       agent role definitions
SPECS/               PRDs and specs
TASKS/               task plans, handoffs, and durable reports
```

The repo overview document — what this codebase is, how it is built, and its domain background — is named in `AGENT_CONFIG.md`. Its conventional name is `ARCHITECTURE.md`, but many repos use another name or have none. If none exists, offer to generate one with the `summarize` skill; do not create it unasked.

Keep repo-specific details out of the portable files. They belong in `AGENT_CONFIG.md`.
