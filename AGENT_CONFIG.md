# Agent config

The single source of truth for repo-specific agent behavior. Generated by the `bootstrap` skill; re-run `bootstrap` to refresh it.

Portable behavior lives in `AGENTS.md`, `WORKFLOW.md`, `.agents/roles/`, and `.agents/skills/`. How humans run this repo lives in `README.md`. Neither is duplicated here.

## Project identity

A Python research repo for an LLM prefix-caching benchmark: prompt mutation, prompt organization, inference benchmarking against vLLM and SGLang backends, and analysis. Pipelines are orchestrated through SLURM batch scripts at the repo root.

Agents should read `README.md` and the per-module READMEs for how the pipeline actually runs, and should not assume domain behavior the code does not show.

## Tests

There is no maintained automated test suite. `prompt_mutation/test_validation_severity.py` is a post-processing script despite its name, and the `test_*.ipynb` files are exploratory notebooks.

Consequences for agents:

- Do not report "tests pass" as evidence. State plainly that validation is manual.
- When adding code, propose targeted tests rather than assuming coverage exists.
- Validate by inspecting behavior and outputs, and say exactly what was and was not checked.

## Git policy

- Staging allowed: **yes**
- Committing allowed: **yes**
- Pushing allowed: **yes**
- Branch policy: work on `main` is acceptable; branch when a change is large or speculative.

Use exact scoped commands (`git add -- <files>`), never `git add .`. Commit only after `review` approves. Never stage generated outputs or local scratch notes.

Sub-agents never stage, commit, or push regardless of this setting — only the agent the user is talking to may do so, and only when asked.

## Domain-specific review risks

Reviewers should always check for:

```text
benchmark measurement validity — is the reported effect caused by the manipulation
  or by cache state, ordering, or warmup
cache on/off control conditions actually differing as intended
prompt mutations preserving the semantic class they claim
overlap and severity metrics matching their stated definitions
config drift between pipeline_config.sh and what a run actually used
stale outputs/ artifacts presented as current results
conclusions drawn from a single seed or a single mutation type
```
